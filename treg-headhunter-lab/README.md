# treg × 猎头场景验证

从岗位需求出发，验证公开网页检索、公司研究和职业线索查找能否帮助猎头形成寻访方向。

本次研究日期：2026-10-28。交付包含研究、6次真实数据调用的记录，以及可以本地运行的研究台。没有测得人工时间节省，也未验证候选人推荐效果。

## 在线研究版

[在线研究版](https://treg-headhunter-field-study.yuna-cyh545439.chatgpt.site)目前仅站点所有者可访问。支持研究浏览、方向生成、回放、来源核实与导出；实时付费接口尚未接入线上。

静态源码位于 `web/`，在该目录执行 `python -m http.server 8000` 后打开 http://127.0.0.1:8000 。

## 启动

2026-10-29更新：[来源核实工作台](docs/source-review.md)。支持待核实/已确认/已排除、原文与理由、业务分类、浏览器保存、筛选和随研究记录导出；网站内新增三家公司官网核查示例。

需要 Python 3.10 或以上，不需要安装依赖。在本目录运行：

```powershell
python server.py
```

打开 [本地研究台](http://127.0.0.1:4386)。点击“查看本次实测回放”可直接查看保存的公开来源；修改岗位、业务、地点和能力可生成新的寻访假设。没有凭证时，实时查询按钮不可用。

网站上方新增“应用机会”：7类场景可按验证程度筛选和展开，查看输入、输出、成本、限制及下一步验证；下方保留可操作的寻访原型。

实时模式需要自己的 treg 团队令牌，在本机服务端设置环境变量 `TREG_TOKEN` 后重启。个人令牌还需要 `TREG_ORG`；团队令牌本身携带团队。不要将令牌写入网页、仓库或研究导出文件。已连接的 MCP 授权不能自动转交给独立网页。

实时模式每次按钮执行1次搜索，上游请求要求5条结果，页面最多显示10条。单次路由限额 $0.01；本次进程按每次 $0.01 预留，最多10次，即使失败也不释放预留。进程重启额度会重置，因此这不是账户月度预算。网络结果未知时需核查账单。回放不调用接口、不计费。

## 当前边界

岗位字段由使用者填写；第一版通过规则形成搜索组合，不包含大模型 JD 自动解析。公司页面用于业务线索；个人经历、任职变化、意愿和最终推荐由人复核。实时查询失败不会回退为示例结果。回放明确显示原始案例，与当前填写内容独立。JSON 可导出供继续标注。

## 后续验证

用5个真实但脱敏的JD，与猎头手工流程做交叉对照；记录达到3条合格公司线索需要的时间、来源可达率、人工复核耗时及单条可用线索成本。通过这些测量再决定是否接入人才工作台。

研究记录、源码与运行说明随本项目一同维护。
