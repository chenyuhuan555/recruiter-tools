# 来源核实工作台 · 2026-10-29

从搜索结果到寻访依据，多了一步可保留的研究判断。本次增加状态、原文依据、判断理由、业务分类和核实时间。

## 使用

打开实测回放或取得查询结果后，在每条来源的“记录核实依据”中填写。状态为待核实、已确认、已排除；业务分类为同类业务、相邻业务、暂不确定。确认必须同时填写原文和理由，排除必须填写理由。

保存后可按状态筛选。核实绑定原始查询与链接，相同URL在不同查询下互不覆盖；修改上方岗位不会改写旧查询的判断。重载页面会恢复已加载结果及保存的核实记录。记录保存在当前浏览器同一站点内，不自动跨设备或跨本地/线上地址同步。导出JSON包含查询、来源、状态、分类、原文、理由和保存时间。未点击保存的编辑草稿不进入导出；本版暂未提供导入功能。

“已确认”只是使用者对具体依据的研究判断，不是公司全部信息已核实，更不是候选人匹配或录用结论。原文由使用者填写，本版不自动验证摘录是否与页面完全一致。

## 官网核查案例

虚构岗位：上海HR SaaS AI产品经理，关注招聘流程产品。用网页读取工具访问三家公司官网，未增加treg计费调用。

|来源|本次观察|研究判断|仍需核实|
|---|---|---|---|
|[北森](https://www.beisen.com/)|官网可读，展示“一体化HR SaaS X AI”与招聘管理产品|同类业务，确认可进入业务研究起点|具体团队、上海岗位及个人经验|
|[Moka](https://www.mokahr.com/)|本轮读取工具超时|待核实；昨天成功提取只作历史观察|当前页面可达性及具体产品内容；工具超时不能证明官网下线|
|[图灵量子](https://www.turingq.com/)|官网可读，强调光子芯片与量子计算|从本示例直接来源公司中排除，分类保留暂不确定|不据此否认其全部员工可能有可迁移经验|

页面里的研究案例与“我的核实”分开；研究者示例不会自动覆盖个人判断。结构化记录见 [review-study.json](../data/review-study.json)。

## 这次能得出什么

对同一示例，能读取且业务相关、读取失败、能读取但业务不相关是三种不同结果。来源状态使三者不再混在搜索摘要里；保留原文和理由，使后续讨论有依据。

此次没有客户确认、候选人筛选或人工对照计时，不能据此计算节省时间。下一步仍应在真实脱敏JD上观察：多少来源经人工接受、核实总耗时及每条有效线索成本。
